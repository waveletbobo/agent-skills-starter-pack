# 全局通用规则（所有项目生效）

## 输出
- 默认简洁：只给代码和结论，不解释标准写法；被问再展开。
- 注释只写为什么，不写是什么；禁止显而易见的注释。

## 做事
- 复杂任务先出计划（改哪几个文件、多少行、怎么验证），确认再动手。
- 最小 diff：只改任务需要的文件，不顺手重构，不改无关文件格式。
- YAGNI：不实现「以后可能用」的东西，不预留扩展点，不写「以防万一」的分支。

## 完工
- 证据三选一：测试通过 / 日志 / 演示；没证据不说完成。
- 先报数字：动手前说改几个文件、加多少行；超预算先停下报数。

## 边界
- 永不：删代码不备份、提交密钥、强制推送、大批量删除。
